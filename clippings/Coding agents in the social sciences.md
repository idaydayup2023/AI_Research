# Coding agents in the social sciences

## 原文信息

- 原文链接：<https://www.anthropic.com/research/coding-agents-social-sciences>
- 发布时间：2026-05-27
- 来源：Anthropic Research
- 作者：Thomas Lyttelton, Maxim Massenkoff, Nathan Wilmers

## 核心提取

Anthropic 调查了 1,260 名社会科学家。81% 的受访者尝试过在研究中使用 AI chatbots，但只有 20% 每周规律使用 Claude Code、Codex、Cursor 或 Antigravity 这类 coding agents。采用者与非采用者之间存在明显差异：男性姓名研究者使用 coding agents 的比例约为女性姓名研究者两倍，顶尖高校研究者更可能采用。

作者谨慎指出，coding agent 用户报告更多 working papers 和 grant proposals，但这可能来自早期采用者本身的差异，不能直接证明因果。

## 中文译读

### Chatbot 普及，不等于 agent 普及

这篇最有价值的地方，是把“用过 AI”和“把 coding agent 放进真实研究流程”分开。很多研究者已经用 chatbot 写代码、改文字、辅助阅读，但真正让 agent 自主写分析代码、运行结果、解释输出、迭代分析的人仍是少数。

这对企业 AI 采用也有迁移价值：组织里“大家都在用 ChatGPT/Claude”并不代表 agent workflow 已经落地。Agent 落地需要命令行、数据权限、验证流程、研究/工程习惯和容错机制。

### 生产率可能提升，也可能放大不均衡

调查显示 coding agent 用户报告更多研究产出，但作者反复强调这只是描述性差异。真正值得关注的是另一层：如果 coding agents 能加速研究执行，它们也可能放大已有资源差距。更早接触工具、更会配置环境、更有数据和算力的人，会更快把 agent 变成研究杠杆。

这和企业里的 AI 采用非常相似：工具本身不是均衡器。谁有流程、权限、数据和审查机制，谁才更容易把模型能力转成组织产出。

### Agent 会参与“分析选择”

原文最后提醒：社会科学越来越依赖由 AI coding agents 参与的分析决策。这里的风险不只是写错代码，而是 agent 的默认建模、清洗、回归、可视化和解释路径会影响我们如何理解经济与社会。

这比“AI 会不会写论文”更深。Agent 进入研究流水线后，它影响的是问题如何被操作化、数据如何被处理、哪些路径被省略、哪些结论被突出。

## 可复用观点

- AI 采用要区分三层：聊天辅助、工具集成、可验证 agent workflow。
- Coding agent 的影响不是“替人写代码”，而是把分析执行链条自动化，进而改变谁能更快试错。
- Agent 产品落地会放大组织原有差距：流程、权限、数据、验证越成熟，收益越快显现。
- 研究和企业场景都需要记录 agent 的分析选择，否则产出变多但证据链变弱。

## 可加工为公众号角度

- 新角度候选：用过 AI 不等于用上 agent，真正的采用发生在流程里。
