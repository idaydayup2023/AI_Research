# 不想做的事交给AI，想做的事留给自己

## 原文信息

- X Article：<https://x.com/alchainhust/status/2054064607669682293>
- 发布时间：2026-05-12
- 作者：花叔

## 核心提取

这篇文章最有价值的地方，不是再次证明 Claude Code / Codex / Cursor / OpenClaw 这类 Coding Agent 很强，而是提出了一个更适合个人工作流的判断标准：

**判断一件事要不要交给 AI，不是看它能不能自动化，而是看这件事的过程本身有没有快乐。**

作者把“效率最大化”改写成“心力配置最优化”：把没意思、标准化、消耗心力、做完没有回甘的事交给 AI；把好玩、需要琢磨、能带来心流和主体感的事留给自己。

## 中文译读

### 一、AI 的真正价值是省下不该被消耗的心力

作者用早上的两个例子说明：合作品牌报名表、提交 zip、按平台规范改 skill、打包资料，这些事情复杂但无聊，必须做却不带来成就感。把它们交给 Claude Code 后，整个上午的心力损耗几乎为零。

关键不是“效率更高”，而是把本来要消耗在低回报任务上的心力，留给自己真正想做的事。

### 二、不是所有标准化的事都该 Skill 化

作者特别强调：能 Skill 化，不代表应该 Skill 化。

判断标准不是“这件事能不能被 AI 做”，而是“我是否享受这件事的过程”。比如报名表没有快乐，就交给 AI；封面创作有快乐，就留给自己慢慢调。

这与 [[别再把 Agent Skill 当提示词了]] 和 [[How to Use Claude Skills to Automate Any Workflow Full Course]] 形成了一个很好的补充：Skill library 不是为了把人从所有事情里移除，而是为了保护人真正想参与的部分。

### 三、AI 编程像游戏，是因为它把难度调回甜区

作者用心流理论解释 AI 编程的上瘾感：没有 AI 时，不熟悉的功能可能太难，查文档、踩坑、调试超出甜区；完全让 AI 做，人只看它跑，又会掉到甜区下限。

最好的状态是人出主意、AI 执行、人调整方向、AI 再执行。它有一点难度，又能立刻看到反馈，所以像游戏一样让人停不下来。

### 四、工具变强时，主体也容易变弱

文章里最深的一点是：工具越强，使用工具的人越容易被工具定义。Excel 会把人变成“Excel 工人”，AI 因为能做的更多，也更可能把人的边界重塑成“AI 擅长做什么”。

所以“什么交给 AI，什么留给自己”不是效率问题，而是主体性训练。每一次判断，都是重新画自己和工具的边界。

### 五、AI 把必要但不好玩的劳动剥离出去

作者最后把这个问题拉到更大的尺度：AI 没有解决所有劳动，但它开始帮人剥离“自己不愿意做但必须做”的部分。剩下的时间用来做什么，就成为一个新的问题。

这正好接上当前知识库关于 Skill、Agent workflow、内容生产自动化的讨论：自动化的目的不是让人消失，而是让人更多停留在判断、创造、审美和心流里。

## 可复用观点

- 自动化的目标不只是效率最大化，而是心力配置最优化。
- 能 Skill 化不代表应该 Skill 化，关键看过程本身是否有心流。
- AI 编程的爽感来自人机协作把任务难度调回甜区。
- Skill library 应该保护人的创造力，而不是把所有过程都剥夺掉。
- 使用 AI 的核心能力之一，是持续判断“交给 AI / 留给自己”的边界。

## 可加工为公众号角度

- AI 不是效率工具，是心力分配工具。
- 什么该 Skill 化，什么不该 Skill 化？
- Agent 时代的主体性训练：不要被你最常用的工具定义。
