# How AI Agents Reshape Knowledge Work

## 原文信息

- 原文：<https://research.perplexity.ai/articles/how-ai-agents-reshape-knowledge-work>
- 技术报告：<https://arxiv.org/abs/2606.07489>
- 来源：Perplexity Research
- 发布时间：2026-06-08
- 作者：Jeremy Yang, Kate Zyskowski, Noah Yonack, Jerry Ma

## 核心提取

这篇文章的价值不在于再次宣称 Agent 提效，而在于给出了一组来自真实产品使用的比较口径：Perplexity 把 Search 视为“检索与综合助手”，把 Computer 视为“跨工具执行的通用 Agent 编排器”，再用近似相同初始 query 的 session pair 比较两类系统。

关键结果有三类：

- **自治时间显著拉长**：Computer 在匹配任务上平均执行约 26 分钟机器工作，而 Search 平均约 33 秒。这说明 Agent 把用户原本需要手动拆解、跨工具执行、检查中间结果的工作吸收到机器执行层。
- **人类后续互动从澄清转向复核和扩展**：Computer 返回更完整交付物后，用户更常做 review、revision、extension，而不是继续追问事实或要求格式修正。
- **任务边界被重组**：Computer query 更常跨职业边界、更偏高阶认知、更常要求多个知识领域和复合工作活动。也就是说，Agent 的影响不只是让旧任务更快，而是让个人开始承担过去需要多个角色协作的组合任务。

## 中文译读

对公众号主线最有用的一句转述是：**Agent 的核心变化不是“回答更好”，而是把知识工作从“人操作流程”改成“人监督流程”。**

Search 的默认分工是：系统回答，人类执行。Computer 的默认分工是：人类说明目标、补上下文、审查结果，系统完成更多中间操作。于是人的瓶颈从“手动做”变成“说清楚目标、提供判断标准、检查结果是否可用”。

这也解释了为什么单纯用“节省多少时间”理解 Agent 不够。节省时间只是第一层，任务重组才是更深的层：当执行成本下降后，人会开始尝试更大、更复合、更跨领域的任务。长期看，组织角色如何打包、团队如何分工，可能比单个任务提效百分比更重要。

## 可复用观点

- Agent 不是搜索增强版，而是执行层外包：它改变的是 intent 和 delivered output 之间的劳动分配。
- 评估 Agent 价值时，不能只看速度，还要看任务范围是否变宽、认知层级是否变高、人的后续反馈是否从“继续解释”转向“复核与延展”。
- 真实使用数据提示：用户采用 Agent 后未必减少 Search 使用，反而可能增加。这说明 Agent 会扩大问题空间，而不是简单替代旧工具。
- 成本口径必须同时计算机器执行成本、人类监督成本和原本人工跨工具操作成本，否则会低估 Agent 的经济影响。
