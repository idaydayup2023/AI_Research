# 编辑指令（最高优先级）

使用者可以修改本文件来调整选题、读者、口吻和禁区。它高于 `automation/ai-research/task-prompt.md`。

## 目标读者与定位

- 读者：产品、工程、管理混合人群，具备基础但不希望阅读论文精读。
- 定位：二次加工的观点文章，不是资讯摘要、逐段翻译或论文读书笔记。

## 写作口吻

- 段落标题友好、直观、凝练，避免正式编号和学术腔。
- 标题先做 5 个候选；近期否定句式密集时优先动作型、隐喻型或判断型标题。
- 开头 3 段内给出鲜明判断或问题，并说明文章解决的读者痛点。
- 概念纠偏稿优先加入具体工程现场或反例。
- 不写形容词堆叠式赞美和空泛趋势判断。
- 不把工具或产品名本身当成观点，必须提炼可迁移机制。

## 选题优先级

- Agent 系统工程：Harness、Skills、Context Engineering、Tool Use、轨迹、权限、审计和可复现性。
- Coding Agents：评测、可靠性、开发者工作流和企业落地。
- Inference、Caching、Serving、成本与延迟/吞吐权衡。
- 知识管理：知识层、证据链、检索、记忆和可迭代内容系统。
- Google DeepMind、Anthropic、Perplexity 等机构的重要模型与研究进展。

谨慎处理纯营销、活动预告、轻量公告、过窄垂直论文和迁移价值弱的纯理论研究。

## 去重与结构

- 同一核心论点和叙事框架近期出现超过 2 篇时，新稿必须更换问题对象或讲述路径。
- 同日多篇文章使用不同叙事角度。
- 必须形成比单篇来源更深入的中心观点。
- 文末必须有 `## 参考链接` 与 `## 关联笔记`。
- 关键判断落到链接、数据口径、对比、反例或可复现流程。

## 规则进化

- 单篇材料不能直接升级为硬规则。
- 弱信号只记录；重复问题或多来源证据进入候选。
- 低风险校验和记录改进可版本化应用。
- 选题、来源、数量、口吻、发布和审批边界变更必须人工确认。
- 候选规则进入 `editorial/editorial-guidelines.candidates.md`，由使用者定期合并。

## 发布边界

内容自动化不得自行执行 Git 发布。Git commit、push、PR、release 和 tag 必须由当前对话中的独立人工指令授权。
