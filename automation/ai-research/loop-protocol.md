# ai-research 双层 Loop 协议

## 内层：单次运行

每次运行必须按以下状态推进：

1. `Sense`：读取规则、配置、memory、历史稿、来源增量和运行锁。
2. `Plan`：列出候选、历史对照、预期产物和验收条件。
3. `Act`：生成摘录、文章、封面、审稿、图谱和复盘。
4. `Evaluate`：检查证据、差异化、链接、文件、比例、回链和 memory。
5. `Repair`：只修复明确未通过项。
6. `Persist`：保存产物、差分、复盘、memory 和下次优先级。
7. `Stop`：满足停止条件后结束。

### 停止条件

- 必需产物存在，或“不生成”已有合规理由。
- 主编审稿必改项已关闭；无法关闭的事项已标注需人工确认。
- 引用、关联笔记、封面、图谱回链和 memory 已校验。
- 没有未处理的高风险规则变更。

### 循环上限

- 自动修订最多 3 轮。
- 同一问题连续 2 轮未关闭，停止自动修改并请求人工判断。
- 每轮必须由具体失败或未满足验收条件触发，不得用“继续优化”作为理由。

## 外层：跨运行改进

外层链路：

`运行轨迹/审稿差分 -> 重复模式 -> 候选 eval -> harness patch -> 历史回放 -> 发布或回滚 -> 新证据`

- 单次弱信号只记录。
- 最近 7 次重复出现，或获得多来源强证据，才进入候选规则或流程改进。
- 低风险、可回滚的记录和校验改进可自动应用，但必须升级任务包版本并记录 CHANGELOG。
- 选题方向、来源范围、数量、成稿门槛、口吻、发布判断和审批边界只能进入候选，等待人工确认。

每次复盘记录：`loop_count`、触发返工的验收项、外层学习信号、`stop_reason` 和 `carry_over`。
