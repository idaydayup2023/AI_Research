# 科学智能体不是博士替身，而是研究流水线

![封面](../covers/2026-05-20-scientific-agent-workbench.png)

Google 这次关于 Co-Scientist、ERA 和 Gemini for Science 的集中发布，最容易被误读成一句热闹话：AI 要替科学家做研究了。

我更愿意把它看成一个更朴素、也更重要的信号：**高价值 agent 不是“万能专家”，而是把复杂知识工作拆成可验证的研究流水线。**

这篇文章想解决的痛点很具体：如果你正在做企业 agent、研究助手、内容生产系统或内部分析工具，别再把目标设成“让一个 agent 从头到尾像专家一样回答”。真正能落地的方向，是把工作流拆成几个稳定工位：提出候选、查证证据、执行实验、排序方案、交给人判断。

## 别造万能博士

Co-Scientist 的结构很有意思。它不是一个“科学家人格”的聊天机器人，而是一组角色明确的 agent coalition：

Generation agent 负责提出初始假设；Proximity agent 负责把假设空间聚类，避免只在局部打转；Reflection agent 像虚拟同行评审，专门挑错；Ranking agent 用成对比较和辩论给候选排序；Evolution agent 把高分假设继续融合、改写；Meta-review agent 汇总过程并生成研究提案。

这套结构的启发不在科研本身，而在分工方式：**多 agent 的正确用法，不是给模型套上不同人格，而是把方法拆成不同工序。**

很多企业内部 agent 做不好，问题恰恰出在这里。它们把“分析一个市场机会”“评估一个供应商”“写一份技术方案”全部交给一个大而全的 prompt。结果输出看起来完整，但你很难判断：哪些是事实，哪些是推断，哪些已经被验证，哪些只是顺口一说。

Co-Scientist 给了一个更稳的答案：先把“想法、证据、批评、排序、提案”拆开。拆开以后，每一步才可能被检查。

## 失败现场：漂亮结论最危险

你可以想象一个很常见的内部场景：

某个团队让 agent 帮忙判断“要不要进入一个新行业”。agent 很快给出一份完整报告：市场规模、竞争格局、进入策略、风险清单，甚至还写了路线图。大家一看格式漂亮、逻辑顺，就开始基于它开会。

真正的问题通常要到几周后才暴露：

- 市场规模引用了过期数据，但报告没有把来源风险标出来。
- 竞争对手名单看似完整，却漏掉了最关键的新进入者。
- 风险清单里有很多正确废话，却没有把“会让项目立刻失败”的假设单独拎出来。
- 路线图写得像计划，实际上没有任何可验证实验。

这不是模型“不聪明”。这是系统没有把工作拆成可审计的环节。没有独立的证据检查，没有反方评审，没有候选排序，没有实验设计，最后只能靠一篇漂亮报告制造确定感。

## 真正的中间层是实验

ERA 补上了另一个关键环节：把假设变成可运行实验。

Google Research 对 ERA 的描述很直接：给它一个科学问题和成功度量，它会搜索文献、写代码、探索方案、组合技术并评估结果。它不是只写一段代码，而是用 tree search 在大量方案里优化输出代码。

这件事对所有知识工作都有迁移价值。因为很多高价值工作并不缺“建议”，缺的是把建议变成可验证实验的中间层。

在科研里，这个中间层是模型、数据、指标和实验代码。在产品里，它可能是 A/B 方案、用户访谈脚本、竞品对照表、价格敏感度测试。在工程里，它可能是 benchmark、回归测试、灰度指标、故障注入。

如果你的 agent 只能写建议，它只是顾问。如果它能把建议转成可运行实验，它才开始接近生产力系统。

## 三个工位，比一个全能 agent 更可靠

Gemini for Science 把这套思路产品化成三个实验工具：

- Hypothesis Generation：基于 Co-Scientist，生成、辩论、评估假设。
- Computational Discovery：基于 AlphaEvolve 和 ERA，生成并评分大量代码变体。
- Literature Insights：基于 NotebookLM，把文献检索、表格化对比、报告和多媒体产出做成知识工作台。

这三个工具不是随便拼在一起的。它们对应科学方法里的三个瓶颈：

想法从哪里来？  
实验怎么跑？  
证据怎么组织？

这比“做一个科学万能 agent”更接近真实工作流。因为研究不是单次问答，而是一条循环：读文献、提假设、做实验、看结果、修正问题、再读文献。

公众号读者如果只带走一个判断，我建议是这个：**复杂知识工作不要先问“能不能自动完成”，先问“能不能拆成几个可验证工位”。**

## 对企业 agent 的启发

这套结构完全可以迁移到企业内部：

做战略分析，不要只要一份报告。至少拆成：资料收集、假设生成、反方审稿、证据表、行动方案。

做研发管理，不要只要一份技术路线。至少拆成：候选路线、关键假设、最小实验、评估指标、失败退出条件。

做内容生产，不要只要一篇稿子。至少拆成：选题雷达、观点生成、资料验证、反例审稿、成稿修订。

这也是为什么最近的 agent 主线会反复回到 harness、skills、runbook、SDK、托管 runtime。模型能力当然重要，但真正决定可用性的，是你有没有把工作过程拆成可复用、可检查、可迭代的系统。

## 结尾：让 AI 做流水线，不要让它装专家

“AI 替代科学家”是一个传播性很强、但工程上很差的说法。

更准确的说法是：AI 正在把研究中的一部分工作变成可计算流程。假设可以成批生成，候选可以互相辩论，代码可以自动变体，实验可以自动评分，文献可以结构化对比。

这不会让人类判断消失，反而会把人类判断推到更关键的位置：定义问题、设定成功度量、选择值得验证的方向、决定什么时候停止。

所以，别急着造“万能博士”。先造一条能查证、能实验、能复盘的研究流水线。
